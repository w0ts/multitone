w0ts / Multitone

A shared way for several Digitone II firmwares to live on one unit and share its +Drive. Design, not built.

What it is

Two things that firmwares can share:

  1. a small boot kernel that can start a firmware kept on the +Drive instead of the one in flash, and fall back to a safe one when that fails;
  2. one shared rule for where each firmware keeps its extra data, how a firmware is named, and how a project made with another firmware is recognised and shown to the user.

How it works

Every firmware carries an identity, brand . name . version (for example Elektron . DN2 . 1.12, w0ts . Wishes . 0.69.6), and a list of the projects it opens, brand . name . min . max. A project records which firmware saved it; another firmware opens it only when that identity is on its list, and otherwise says which firmware made it.

Stock addresses come from one checked table per stock OS version; on a version without a table the kernel switches itself off and the firmware boots as usual. The first table is 1.12.

Adopting it

Planned, not built yet:

  1. add this repository to the firmware as a git submodule;
  2. run the build glue that places the kernel and fills the firmware's identity, open list and ranges;
  3. take a line in the registry by pull request;
  4. build against the address table of the firmware's stock version.

The registry

One line per firmware: number, 4-letter id, brand, name, its block of machine-type numbers, its +Drive ranges and its RAM ranges. A new line may overlap no other, so two firmwares never write the same place or give one machine-type number to two engines. The file is registry/firmwares.txt (a proposal; first entries: Elektron DN2 stock, w0ts Wishes).

Status

Design, not built. Nothing has run on a unit or in an emulator. The licence is not chosen yet, so there is no licence file. Unofficial: not made or supported by Elektron.
